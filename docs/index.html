한글 실시간 통역기 대기 중
아래 ▶ 플레이 버튼 중 하나를 누르면 한 단계씩 애니메이션과 한글 해설이 함께 진행돼요!

🐢 일반 리스트 전수 탐색이었다면 (O(N)) 0개 순회

1. 명령어 입력 & 플레이 시나리오 (직접 치거나 ▶ 버튼을 누르세요)

명령어: SET · GET · DEL · EXISTS · DBSIZE · KEYS · CONFIG SET maxmemory N · INFO memory · EXPIRE · TTL

2. 냉장고 용량 & 3. TTL 최소 힙 2D 트리 (키 위에 마우스를 올리면 3곳이 같이 빛나요!)

used_memory 0B maxmemory 0B evicted_keys 0 keys 0
무제한(0). CONFIG SET maxmemory 30 으로 제한해 보세요.
완전 이진 트리 (가장 급한 키 = 0번 꼭대기) 루트 peek() → O(1)

4. LRU 양손 기차 줄 (DoublyLinkedList) — 방금 쓴 칸은 #1 1등석으로, 안 쓰는 칸은 오른쪽 끝으로!

🟢 1등석 안전 구역 (MRU: HEAD 바로 뒤)
안 쓸수록 오른쪽으로 밀려남 ──▶
🔴 퇴거 위험 구역 (LRU: TAIL 바로 앞)
🚂 각 칸은 왼손(prev)과 오른손(next)을 맞잡고 있어, 어떤 칸이든 고리 4개만 바꿔 O(1)로 맨 앞으로 이동합니다.

5. 해시맵 우편함 & 체이닝 (HashMap) 🚀 적재율 0.75 초과! 우편함 2배 자동 증축 완료!

📮 우편함 포화도 (적재율 = 저장된 키 ÷ 전체 칸 수) 0 / 16 = 0.00 (0.75 초과 시 2배 증축!)

#15. LRU ➔ LFU 전환 설계
조회 빈도 기반 O(1) 퇴거
  • 빈도 카운트: Record.freq (기본 1, GET 시 +1)
  • 이중 맵+리스트: freq_map[freq] ➔ DoublyLinkedList + 최저 빈도 포인터 min_freq로 O(1) 승격·퇴거
  • 동률·감쇠 정책: 동일 빈도 내에선 LRU 꼬리 제거 + 시간 경과 시 빈도 반감(lfu-decay-time)으로 옛 인기 키 고착 방지
🚀
#16. 10만 건 대규모 병목 & 대책
지연 스파이크 제거 & 수평 분할
  • 리해시 스파이크: ht[0]/ht[1] 점진적 리해싱(매 명령 1버킷씩 이동)으로 순간 정지 제거
  • 힙·Stale 누적: Stale > 2N 시 O(N) 컴팩션 + Redis형 적응형 샘플링 병행
  • CPU·I/O 한계: 16,384 해시 슬롯 샤딩(N개 노드 분산) + 명령어 파이프라이닝 / 비동기 asyncio 전환
